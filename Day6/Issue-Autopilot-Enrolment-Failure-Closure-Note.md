Resolved. Cause: Stale legacy manual MDM enrolment (dated 2023-11-04) still active on the device, never decommissioned before it was reset for Autopilot; new enrolment attempt was rejected as a duplicate (`0x80180014`), which also blocked all 4 configuration profiles from applying (`0x80070005`, Access denied). Action: Located the stale device object in Intune/Azure AD by serial number/hardware hash, deleted the stale Intune device record (and duplicate Azure AD object where present), removed the orphaned enrolment on-device (`dsregcmd /leave` + `MdmDiagnosticsTool.exe` unenroll / Disconnect work account), retriggered Autopilot enrolment, and confirmed successful enrolment with 4 of 4 profiles applied. Azure AD join, Intune P1/Autopilot licensing, and network connectivity were confirmed healthy throughout and were not contributing factors. Preventive: Add a mandatory MDM-cleanup step to the device retirement/reset workflow before Autopilot handoff, sweep the estate for other devices still on legacy manual enrolment, automate the cleanup step, and publish a KEDB entry for this failure signature. Device confirmed working after re-enrolment.
